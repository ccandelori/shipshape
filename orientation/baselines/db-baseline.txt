## Methodology — exact per-flow counts

1. Enabled `pg_stat_statements` in the docker container: appended `shared_preload_libraries = 'pg_stat_statements'` and `pg_stat_statements.track = 'all'` to `/var/lib/postgresql/data/postgresql.conf`, then `docker restart ship-postgres-1`.
2. `CREATE EXTENSION IF NOT EXISTS pg_stat_statements;`
3. For each of the 5 flows:
   - `SELECT pg_stat_statements_reset();`
   - Hit the canonical API endpoints for that flow via curl with a session cookie.
   - `sleep 0.3` to flush async writes.
   - Snapshot: `SELECT calls, ROUND(total_exec_time::numeric, 3), ROUND(mean_exec_time::numeric, 3), rows, query FROM pg_stat_statements ORDER BY total_exec_time DESC;`
4. Filtered out database admin/meta statements (`BEGIN`, `COMMIT`, `SET`, `SHOW`, `pg_stat_statements%`).
5. For each flow's slowest query (first row of the snapshot), ran `EXPLAIN (ANALYZE, BUFFERS, VERBOSE)` with realistic seed-data parameters (workspace UUID `9dbdd448-…`, super-admin user UUID `e6596c5e-…`).

## Live indexes on `documents`

13 indexes total: primary key + 10 scalar/partial btree indexes + 1 GIN index on `properties` + 1 dedicated expression index:

```
idx_documents_person_user_id ON ((properties->>'user_id')) WHERE document_type='person'
```

That's the only JSONB-path expression index in the schema.

## Index gaps (Phase 2 candidates)

High-value JSONB hot-path predicates with no expression index today:

- `(properties->>'assignee_id')::uuid` — dashboard, issues list, team grid, program/admin filters
- `properties->>'state'` — issue + dashboard filters
- `(properties->>'owner_id')::uuid` — project, program, sprint ownership lookups
- `(properties->>'sprint_number')::int` — week + team-board filters
- `properties->>'priority'` — issue priority sort
- `documents.title ILIKE '%q%'` — needs `pg_trgm` GIN/GIST (leading-wildcard ILIKE is not btree-sargable; explain-flow-5.txt confirms Seq Scan)

## Caveats (carry forward to before/after work)

- Warm shared_buffers — every plan reports `shared hit=N`, no disk reads.
- Seed volume: 104 issues, 500 candidate docs in search. Production scale is unknown.
- Localhost; planning time can equal execution time at small data volumes.
- `application_name` on the API pg.Pool would help separate noise from app traffic — recommend setting `application_name = 'ship-api'` for future captures.

## Recapture command (for Phase 2 before/after)

```bash
# pg_stat_statements is already enabled in the container (postgresql.conf appended
# with shared_preload_libraries='pg_stat_statements'; restart-persistent).
SESSION=$(grep session_id /tmp/ship-cookies.txt | awk '{print $7}')
CONNECT=$(grep connect.sid /tmp/ship-cookies.txt | awk '{print $7}')
COOKIE="session_id=$SESSION; connect.sid=$CONNECT"

pgss_reset() { docker exec ship-postgres-1 psql -U ship -d ship_dev -c "SELECT pg_stat_statements_reset();" > /dev/null; }
pgss_snap()  { docker exec ship-postgres-1 psql -U ship -d ship_dev -P pager=off -At -F $'\t' -c "
  SELECT calls, ROUND(total_exec_time::numeric, 3), ROUND(mean_exec_time::numeric, 3), rows,
         REGEXP_REPLACE(query, '[[:space:]]+', ' ', 'g')
  FROM pg_stat_statements
  WHERE query NOT LIKE '%pg_stat_statements%' AND query NOT IN ('BEGIN', 'COMMIT', 'ROLLBACK')
    AND query NOT LIKE 'SET %' AND query NOT LIKE 'SHOW %'
  ORDER BY total_exec_time DESC;"; }

# Per flow: pgss_reset; <curl walk>; sleep 0.3; pgss_snap > queries-flow-N-after.log
```
