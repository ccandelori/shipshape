# Cat 2 — Bundle baseline

## What's here

| File | What it is | How it's produced |
|---|---|---|
| `bundle-baseline.html` | Interactive rollup treemap of the production web bundle | `regenerate.sh` (uses `rollup-plugin-visualizer` via `BUNDLE_ANALYZE=1`) |
| `build.txt` | Full stdout of the analyzed build (chunk sizes, warnings) | `regenerate.sh` (tee'd from `pnpm build:web`) |
| `files-js.txt`, `files-css.txt` | Sorted lists of dist assets | Manual `ls -S dist/assets` |
| `per-package.txt` | Bytes per node_modules package | Manual analysis |
| `static-analysis.txt` | Unused-export and dead-code findings | Manual analysis |
| `unused-deps.txt` | `depcheck` findings | Manual analysis |

## Regenerating the treemap

```bash
bash orientation/baselines/bundle/regenerate.sh
```

That script:

1. Runs `BUNDLE_ANALYZE=1 pnpm build:web`.
2. Captures the build log to `build.txt`.
3. Copies `web/dist/stats.html` over `bundle-baseline.html`.

The `BUNDLE_ANALYZE=1` flag is wired into `web/vite.config.ts` and only loads `rollup-plugin-visualizer` when set, so normal builds stay fast.

## Why the script exists

The PRD compliance audit flagged that the original `bundle-baseline.html` was generated by an ad-hoc visualizer install that wasn't checked in. Reproducibility was therefore unverifiable. The script + the conditional plugin in `vite.config.ts` close that gap: anyone with a fresh checkout can regenerate the treemap with one command.
