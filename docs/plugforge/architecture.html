Agent Authentication Decision
The internal agent authenticates using the Client Credentials grant (RFC 6749 §4.4) via a dedicated system OAuth app seeded at deployment time.

Rationale: Machine-to-machine (no interactive user), standard OAuth flow for this case, clean audit trail under a distinct client_id. Alternatives (Device Grant or long-lived tokens) were rejected for auditability or unnecessary user interaction reasons.

The agent uses ShipClient.clientCredentials() (or direct token injection) and all its actions appear in the public audit trail exactly like external developers.
Developer Portal
In-app UI (consuming the public /api/v1 surface) for: listing/registering OAuth apps, one-time secret display & rotation, managing subscriptions, browsing delivery logs, and replaying failed deliveries.

Dogfooding note: Portal users authenticate with their normal Ship session. The portal uses that session context to call the public OAuth app registration endpoints (with workspace-admin privileges where required).
Reference Integration & TTFE Drill
A reference CLI implementation (in integrations/cli/, consuming @ship/sdk) proves the platform:
ship login (Device flow) → ship docs create → ship webhooks tail (verified signed delivery).

The Time-to-First-Event (TTFE) drill is the key validation: from a clean machine, pnpm install @ship/sdk → login → create document → receive cryptographically verified webhook. Target: <60s in CI, ≤30min on clean hardware. Runs on every PR.

    actor Sub as Subscriber

    Domain->>Bus: publish("document.created", payload, idempotencyKey)
    Bus->>Matcher: find subscriptions for event + app
    loop for each matching subscription
        Matcher->>Signer: sign(payload, secret, timestamp)
        Signer-->>Deliver: Ship-Signature header
        Deliver->>Sub: POST target_url + Idempotency-Key
        alt success (2xx)
            Deliver->>DB: record success
        else 4xx
            Deliver->>DB: permanent failure (no retry)
        else 5xx or timeout
            Deliver->>Deliver: schedule retry (1s,4s,16s,1m,5m,30m)
            Deliver->>DB: log attempt
        end
    end
    Note over Deliver: After 6 failures → DLQ
Replay re-emits original event
Key invariant: Domain layer publishes. Route handlers never do. In-memory deliverer is synchronous for tests. Real implementation uses deterministic clock injection.
Key Technical Decisions & Rationale (Compound Engineering output)
Public / Internal Boundary as a One-Way Door
HIGH IMPACT
New directory api/src/platform/. All /api/v1 routes and platform services live here or import exclusively from here. A custom ESLint rule + import/no-internal-modules fails the build on violations from internal code.
Why: PRD explicitly calls this a "one-way door". Retrofitting later is far more expensive.
Current hook: api/src/app.ts router mounting + existing lint setup.
OpenAPI Generation — Extend, Do Not Fork
Reuse the mature api/src/openapi/registry.ts + @asteasolutions/zod-to-openapi. Register new v1 schemas and paths. Minor upgrade path to OpenAPI 3.1 generator. Fitness test extends existing openapi tests.
Strong existing pattern — zero greenfield risk here.
Event Bus Introduction (Dependency Inversion)
Define IEventBus immediately. Domain services publish events on writes. First implementation: in-memory (synchronous for tests). Queue-backed (BullMQ/Inngest/SQS) is Liskov-substitutable later.
Prevents the common anti-pattern of webhook logic leaking into route handlers.
SDK as Pure Consumer Package
New workspace package sdk/ (added to pnpm-workspace.yaml). Zero imports from api/src or web/. Hand-written for quality + fitness-tested against generated OpenAPI. Includes pluggable ITokenStore.
Dedicated Public OAuth Middleware
A distinct oauthBearerAuth middleware is used on all /api/v1/* routes. It validates OAuth access tokens (app, user, granted scopes) and produces the correct error codes, including a distinct code for expired tokens. The existing internal authMiddleware (session + legacy API tokens) is not used for the public surface.

References:
SOLID Mapping (required by PRD architecture doc)
OCP — ScopeRegistry: new scopes register at module load. No edits to middleware required.
DIP — IEventBus interface. Domain depends on abstraction; deliverer implementations are swappable.
ISP — SDK resource clients (DocumentsClient, WebhooksClient) are segregated by concern.
SRP — Each platform service owns exactly one cross-cutting concern (auth, scopes, webhooks, rate-limit, audit).
LSP — In-memory and queue-backed deliverers are substitutable; tests use the in-memory one.
Failure Modes (required by PRD)
Token store corrupted — Affected OAuth clients receive clear, actionable errors. Existing sessions and legacy API tokens are unaffected. Client secrets can be rotated through the developer portal.
Webhook secret rotated mid-flight — Every delivery attempt uses the secret currently active for the subscription at signing time. Replay uses the active secret at the time of replay. No secret versioning.
Queue deliverer crashes — At-least-once with idempotency keys; subscribers must be idempotent. webhook_deliveries table records subscription_id, event_id, attempt_number, response_status, response_excerpt, latency_ms (queryable per app).
OpenAPI generator throws at boot — Fail fast with clear message; registry is validated in CI.
Event Registry
Event types are data with Zod schemas (in platform/events/definitions.ts). Required events include: document.created, document.updated, document.deleted, issue.created, issue.assigned, issue.status_changed, sprint.started, sprint.completed. New events are registered at module load (OCP).
